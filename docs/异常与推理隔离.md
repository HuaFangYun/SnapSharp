# 异常记录、热键与推理隔离

## 异常记录

启动时注册 WPF Dispatcher、AppDomain 和未观察任务异常处理器，退出时注销。普通 UI 异常会记录并显示带“复制错误信息”按钮的对话框，随后允许继续操作；程序状态是否仍完整取决于抛出异常的操作。内存不足、访问冲突等可检测的致命异常记录后退出。CLR 无法回调处理器的原生硬崩溃、栈溢出或操作系统强制终止无法保证落盘。

记录位于数据目录的 `Diagnostics/crash-yyyyMMdd-HHmmss-唯一标识.txt`，包含异常类型、HRESULT、调用栈、系统、.NET 和内存占用。同一秒的多条记录不会覆盖。为避免异常消息夹带 OCR 原文、文件路径等用户内容，不记录 `Exception.Message`、`Data`、源码文件路径、截图或识别结果，也不创建会包含进程内截图和 OCR 数据的二进制内存 dump；这里的崩溃转储为文本诊断记录。

## 全局热键

注册成功的 ID 仅接受 `WM_HOTKEY`，使用 `MOD_NOREPEAT`。注册失败的 ID 才加入 25ms 轮询，失败的 ID、action、组合键和系统错误码追加至 `Diagnostics/hotkey-status.log`。没有失败项时停止轮询计时器。

轮询在主键释放后才重新启用；长按期间切换修饰键不会再次触发。移除跨 action 的 250ms 节流，用 action 集合阻止回调重入。系统注册失败的兜底只能检测组合键，不能阻止占用此快捷键的其他程序也响应。

## ONNX 子进程

PaddleOCR、公式、表格和抠图通过 `SnapSharp.exe --onnx-worker` 执行。子进程在单实例和托盘初始化前分流；主进程不创建 ONNX 原生会话。Windows OCR、Tesseract、条码以及本地翻译保持各自原有路径。

图片以 PNG、结果以结构化消息在仅限当前用户的随机命名管道中传输，不创建图片或 OCR 临时文件。每次操作启动一个进程，父进程串行调度；同一操作仍最多缓存四个会话。操作结束、失败或取消都会释放/终止子进程，因此跨请求不再保留模型缓存，换取原生内存与故障边界清晰；大型模型重复操作会增加加载延迟。

DirectML 初始化或推理异常先释放失败会话再用 CPU 重试。GPU 子进程异常退出也会在剩余超时内以 CPU 新进程重试；同一适配器在本次应用启动期间随后使用 CPU，不修改已保存的设备选择。CPU 子进程失败只丢弃本次结果。超时与取消会结束本次进程。

DXGI 查询子进程适配器的本地显存预算与占用，会话创建前后达到预算的 90% 时改用 CPU；设备不支持查询时继续依靠异常回退和进程隔离。该预算不是精确的单模型显存预测，单次原生调用仍可能超配，因此不能保证 GPU 推理永不失败。`Diagnostics/inference-status.log` 只记录设备回退、预算及进程状态，不记录图像或识别文字。设置页展示 GPU 风险和 CPU 建议。

专项验证见 [StabilityChecks](../tools/StabilityChecks/README.md)。
